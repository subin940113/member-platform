# AI 활용 기록

AI는 설계 초안 정리와 반복 작업을 줄이는 데 활용합니다.  
다만 최종 구조와 정책은 코드 기준으로 직접 확인하고 반영합니다.


## 사용 도구

- **ChatGPT**
  - 요구사항 해석과 동시성, 토큰, 개인정보 처리와 같은 설계 초안 정리
  - 개념 검증 및 설계 방향 탐색

- **Cursor**
  - Java, Spring Boot, Gradle 기반 멀티모듈 구조 생성
  - 테스트 코드 및 리팩터링 초안 작성
  - README, DECISIONS 등 문서 초안 정리


## 활용 방식

요구사항과 구현 범위를 먼저 정리한 뒤, 그 범위 안에서만 질문합니다.  
동시 가입 처리, 토큰 구조, 개인정보 처리 방식처럼 선택지가 갈리는 주제는 먼저 비교해 보고, 현재 범위에 맞는 방향만 반영합니다.

AI 답변은 초안으로만 참고하고, 코드와 설계에 맞는지 확인한 뒤 반영합니다.  
유스케이스 경계, 인증 구조, 개인정보 정책과 같은 주요 결정은 직접 정리합니다.


## 유용했던 부분

- **DB UNIQUE 기반 동시성 방어**  
  DB를 최종 정합성 보장 수단으로 두고, 애플리케이션은 예외를 해석하는 구조

- **Access / Refresh 토큰 구조**  
  stateless Access Token과 DB 기반 Refresh Token 관리 구조

- **Spring 계층 구조**  
  `@Service` 중심의 유스케이스 구성과 예외 매핑 방식

- **문서 및 테스트 초안**  
  README, 보안 문서, 테스트 코드의 초기 구조 구성


## 보완한 부분

- **과도한 계층 분리 제거**  
  현재 규모 대비 복잡도가 높은 구조는 단순화했습니다.

- **동시성 처리 기준 정리**  
  선행 검증이 아닌 DB 제약을 기준으로 정합성을 정의했습니다.

- **테스트 환경 정합성**  
  H2 대신 PostgreSQL 기반으로 환경을 통일했습니다.

- **부적절한 제안 제외**  
  rate limit, equals/hashCode 자동 생성 등 불필요한 요소는 제거했습니다.


## 주요 기여

- **정합성 설계 확정**  
  DB UNIQUE를 기준으로 동시 가입 처리 구조를 정의하고, 통합 테스트로 실제 동작을 검증했습니다.

- **인증 및 세션 모델 정리**  
  Access / Refresh 구조와 ACTIVE 상태 검증, revoke 및 rotation 정책까지 포함해 인증 흐름을 구성했습니다.

- **개인정보 처리 정책 정의**  
  암호화, 해시, 마스킹을 역할별로 분리하고, 저장·조회·노출 기준을 정책 단위로 정리했습니다.

- **관리자 접근 및 감사 로그 설계**  
  PII 조회를 별도 API로 분리하고, 모든 민감 접근을 감사 로그로 추적 가능하도록 구성했습니다.

- **운영 관점 반영**  
  캐시 장애 시 DB fallback, 토큰 revoke 전략, 로그 노출 제한 등 운영 상황을 고려한 설계를 적용했습니다.

- **모듈 경계 및 문서 정합성 정리**  
  Gradle 의존 규칙을 명시하고, 코드·문서·테스트가 동일한 기준을 따르도록 정리했습니다.


## 정리

AI는 설계 비교와 초안 작성, 반복 작업을 줄이는 데 활용합니다.  
다만 최종 반영 여부는 코드와 요구사항 기준으로 다시 확인하고 결정합니다.
